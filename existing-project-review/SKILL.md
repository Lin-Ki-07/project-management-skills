# 已有项目体检

先确定用户要继续开发或修复的范围，再检查适用说明、Git 状态、相关代码和可运行入口。优先验证一条核心链路；无法调用外部服务时，做离线检查并明确未覆盖部分。不要仅凭路线图、注释或“AI 味”判断功能和质量。

按证据整理短清单：**已证实问题、待验证风险、可选优化**。每项写清位置、触发条件、预期与实际、证据、影响、建议的最小修复及验收方式。先处理数据或核心流程风险，再考虑高频问题和维护成本；架构调整须有具体耦合或变更成本证据。

需要检查范围、证据等级和排序细节时，阅读 [体检方法](README.md)。体检只形成可讨论的修复顺序；用户选定小目标后再进入实施。保留不明用途文件，不把体检自动扩成全面重构。

需要记录报告时，可使用 [体检记录模板](assets/REVIEW.md)，按用户选择的交付形式填写；已有报告则沿用格式，不覆盖历史证据。需要参考结论分类、补验条件及修复交接时，按需阅读 [体检报告案例](references/review-example.md)。案例为虚构试填，不能作为实际项目的运行结果。
