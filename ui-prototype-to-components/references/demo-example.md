# Demo 设计交接：文章摘要

> 虚构试填，未调用 Image 或 Figma，没有真实设计链接、用户确认或运行验收。不把下文占位说明当成可开发的完整交接。

假设用户已确认轻量 PRD d1：粘贴文章，经真实模型返回摘要，空输入和请求失败有明确反馈。账号、历史记录和同步不在本轮。已有清晰视觉参考，因此跳过额外案例调研。

## 最小设计过程

1. 生成一个代表页面的效果图，评审布局、配色和信息层级，取得视觉定稿依据。效果图到此完成职责，不能直接交给开发照图实现。
2. 依据视觉方向在 Figma 制作可编辑界面，覆盖输入、处理中、成功和失败。准确落实文字、间距、状态及操作，不把整张效果图贴入 Figma 冒充原型。
3. 评审操作路径及状态，记录对应页面或节点和确认依据。实现读取 PRD 与 Figma，效果图只作视觉决策背景。

## 状态与组件交接试填

| 状态 | PRD 行为 | Figma 入口 | 实现验收 |
| --- | --- | --- | --- |
| 输入 | 输入文章并提交，空输入提示补充 | 待实际制作后填写 | 空输入不调用服务；非空可提交 |
| 处理中 | 展示请求正在处理，避免重复请求 | 待实际制作后填写 | 实际请求中状态可见，不重复发送 |
| 成功 | 展示本次真实模型摘要 | 待实际制作后填写 | 内容来自实际调用，界面对应 Figma |
| 失败 | 显示失败并允许重试 | 待实际制作后填写 | 可控失败后反馈明确，重试重新发起调用 |

输入区负责文章内容及提交事件，结果区承载处理中、成功与失败状态；组件可沿用项目现有组织，不先建完整组件库。视觉示例文章及摘要只作设计占位，不能成为运行时预设答案。“避免重复请求”等未在 PRD 中确定的业务行为，应先提出并确认，不能由原型静默新增。

当前一步为完成并确认实际 Figma 状态与链接，之后才交给实现。本例缺少这些真实产物，因此不能标记原型完成。原型内未连线的状态标为“仅状态展示”，不宣称交互已验证。

## 工具阻碍与后续变化

若 Figma 连接失败，先核对连接、权限和文件访问，对可恢复问题有限重试。仍不可用时说明阻碍，再与用户讨论 HTML 兜底；不预先生成 HTML，也不为此擅自选择最终前端框架。采用兜底时注明临时依据，不能声称已有 Figma 设计。

若后续只调整摘要区间距，直接更新相关 Figma 节点并同步交接，无需重做效果图和全部页面；若核心业务规则变化，先更新受影响 PRD 并确认，再同步设计。
