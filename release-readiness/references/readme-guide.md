# 项目 README 编写规范

## 先核实再写

读取现有 README、真实目录、运行入口、依赖配置、示例配置、测试入口与许可证，结合用户指定读者和项目阶段确定篇幅。修改旧文档时保留仍有效的信息与已有用户改动，不根据模板重建整个项目说明。

先回答读者最关心的问题：项目解决什么、当前能做什么、怎样开始、到哪里看代码、有什么限制。Demo 用短版即可；复杂安装、API 和部署细节链接到专项文档，不把内部开发日志搬进首页。

## 结构与展示

- 首屏放名称、具体定位及有帮助的截图或总览图；导航用于篇幅较长的 README，不强制堆装饰。
- 功能用实际场景表达，配可复制用法。截图注明实际界面或设计示意；流程图不能冒充实际运行证据。
- 徽章只表达可核实的许可证、版本、CI 等事实；没有排名、认证、兼容性验证时不添加相应标识。
- 目录树从真实文件生成或核对，先展示仓库整体，再按需展开一个代表模块。不用虚构的聚合目录伪装现有布局；省略部分明确写为节选，避免长树和重复说明。每条注释解释职责，关键入口可再给链接。
- 同类信息用表格比较，步骤用编号，命令用标明语言的代码块。图片用相对路径、替代文本和适当尺寸，避免只在某个主题下可读。

## 运行与事实边界

- 安装、配置、启动和验证命令来自当前项目；注明运行目录、环境条件、入口与预期结果。未实际执行的命令写明未验证，不为改文档强行调用付费服务或部署。
- 已实现能力、模拟、待验证和计划分开。不要把构建通过写成真实交互通过，也不承诺未经证实的性能和平台兼容性。
- 示例配置使用安全占位值，不包含凭据、私人数据或本机绝对路径。许可证与反馈入口依据实际仓库，不替用户决定许可。
- 修改行为或入口后同步相关段落；计划放路线图，过程放日志，README 保持当前使用说明。

## 收尾核对

核对文件链接、标题锚点、图片引用、目录结构、代码块和命令来源；有渲染条件时查看最终页面，未渲染就如实说明。不因模板要求添加无内容章节，删除未填写占位符。最后报告改动、检查范围、未验证项、建议提交信息与下一步。
