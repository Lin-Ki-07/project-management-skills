# 需求收敛案例：个人阅读清单

> 本案例为虚构对话和模板试填，没有真实访谈、市场调研、用户确认或产品实现。示例中的“确认”只说明应记录的形式，不能作为实际项目开工依据。

## 从想法到关键问题

示意用户：“想做一个收藏文章的小工具，最好能自动总结、同步、打标签。”

此时记录：收藏工具是用户提出的方向；列举功能不等于已确定首版。先问使用情境与现有问题，而不是立即选数据库或设计页面。

示意追问：“你主要在什么时候收藏，现有方式最困扰你的是什么？”

示意回答：“电脑上读技术文章，把链接丢在聊天收藏里，之后找不到，也不知道哪些读过。”

据此归纳：目标用户为本人，电脑端使用；核心问题是找回链接和区分阅读状态。自动总结和跨设备同步的必要性尚未确定。

下一轮只澄清会改变首版边界的事项：“首版先解决保存、查找和已读状态是否足够？同一个链接重复保存时，你希望怎样处理？”

示意回答：“够了。先不做总结和同步。同一个链接别重复添加。数据要能在下次打开时保留。”

仍需明确重复判定和删除规则，不能自行把“同一个链接”解释为复杂网址归一化。示意补充回答：“去掉首尾空格后完全相同就算重复；删除前让我确认，首版不做恢复。”

此时核心范围已收敛，可询问 PRD 交付形式。假设示意用户选择“先在对话里展示”，就不自行创建项目文件。

## 按模板试填的 PRD v1

- 文档状态：待确认。
- 确认依据：尚无对本版完整 PRD 的确认。上面的需求回答是整理依据。
- 本轮范围：电脑端个人阅读清单。
- 目标与场景：本人在电脑上保存技术文章，之后查找并记录是否读过；现有聊天收藏不便管理。
- 期望结果：能按标题找到保存的文章，并区分未读与已读。是否提高阅读效率尚未验证。
- 材料依据：上述虚构需求对话；未开展市场或竞品调研。
- 首版包含：手动填写标题和链接、按标题查询、切换阅读状态、确认后删除、再次打开时保留数据。
- 首版排除：自动总结、标签、跨设备同步、删除恢复。它们不自动进入后续版本承诺。

| 编号 | 场景与规则 | 可观察的验收条件 |
| --- | --- | --- |
| R1 | 保存标题和链接，去除两者首尾空格；空内容不保存 | 输入合法标题及 http/https 链接后出现新条目，初始为未读；标题或链接为空、链接格式不合法时提示原因且不新增 |
| R2 | 去除首尾空格后完全相同的链接视为重复，不进一步合并不同 URL | 再次提交同一链接时提示已存在，条目数量不增加；标题不同不影响链接重复判断 |
| R3 | 按标题子串查询，首尾空格忽略，保持区分大小写 | 空查询显示全部；有匹配只显示匹配项；无匹配显示空结果 |
| R4 | 切换已读状态并保存清单 | 切换后状态更新，关闭并重新打开后标题、链接与阅读状态一致 |
| R5 | 删除前确认，无恢复功能 | 取消时保留条目；确认后删除，再次打开也不出现 |

注意：R1 的链接校验和初始未读、R3 的匹配规则是为使草稿可讨论而提出的**助手建议**，此前示意用户没有确认，须在审阅时单独指出。不能因为写进表格就把它们升级为决定。

- 关键数据：标题、链接、阅读状态；内部标识由研发决定。
- 已确认约束（仅示例设定）：电脑端个人使用、下次打开保留数据、不做账号及云同步；具体技术栈未定。
- 未决事项：确认 R1 和 R3 的建议规则；它们影响核心行为，确认前不能开工。
- 可留待设计的细节：按钮位置、空结果的具体视觉样式，不改变上述行为。
- 下一步：展示整版并指出新增建议，请示意用户审阅。

## 审阅、确认与交接

假设后续示意用户明确回答：“确认这份 PRD v1，包含你补充的链接校验、初始未读和搜索规则。”此时才把该示例文档标为已确认，并记录对应对话。若只回答“继续看看”，仍不能推定确认。

交给路线图的摘要为：

> 依据对话中的 PRD v1 及其明确确认，规划 R1—R5 的实施与验收。保留首版边界、重复链接规则、持久化及确认删除规则；总结、标签、同步、恢复暂缓。技术栈与页面布局尚未决定。路线图环节可按依赖拆分步骤，本 PRD 不预设技术任务和工期。

如果用户随后要求增加跨设备同步，应修订受影响的 PRD 并重新确认变化，不能拿 v1 的确认作为新增范围的授权。

## 试填核对

已人工核对：用户回答、助手补充与待定细节有区分；验收包含重复、空输入、无匹配、持久化及删除取消路径；完整 PRD 的确认独立记录；交接引用需求编号而未拆技术任务。此核对仅验证示例内部一致性，没有运行产品或做独立行为评测。
